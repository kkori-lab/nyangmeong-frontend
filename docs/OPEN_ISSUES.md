# 아직 정하지 않은 것

`AGENTS.md`와 `docs/convention/`의 규칙에서 빠져 있는 결정을 모았다. 정해지면 그 문서에 규칙으로 옮기고 여기서 지운다.

## 팀이 정할 것

| 항목 | 지금은 이렇게 한다 |
| --- | --- |
| 브랜치·커밋·PR 규칙 전체(`docs/convention/git.md`) | 그 제안을 따른다. 백엔드 저장소와 같이 정한다 |
| `pages`의 `useQuery` 금지와 `import.meta.env` 직접 읽기 금지도 ESLint로 강제할지. `features` 간 import, `axios` 직접 import, `fetch`는 이미 ESLint가 검사한다 | 사람이 리뷰에서 본다 |
| CI를 설정할지, 무엇을 돌릴지 | 정해지지 않음. 그 전에는 PR을 올리는 사람이 로컬에서 `yarn lint`와 `yarn build`를 돌린다 |
| 테스트를 쓸지, 쓴다면 어떤 도구로 | 정해지지 않음 |
| 스타일링 규칙: 색·간격 토큰, Tailwind 클래스가 길어질 때 | 정해지지 않음. 디자인 시안이 나온 뒤 정한다. 디자인 기준 순서와 AI 슬롭 금지는 `docs/convention/ui.md`에 정했다. **제안(SJM, 2026-10-20)**: 그림자 토큰 이름은 깊이 그림자 `shadow-depth-sm`·`md`·`lg`(Tailwind 기본 `shadow-sm`·`md`·`lg`와 겹치면 다른 화면 모양이 바뀌므로 `depth`를 붙인다), 포커스·오류 링 `ring-focus`·`ring-error`(`index.css`의 `@utility`)로 짓는다 |
| Figma 한도: REST API는 토큰 주인이 View·Collab 시트면 월 20회, Dev·Full 시트면 분당 10회(Starter). Figma MCP는 Starter에서 몇 번 만에 막힌다 | `/start`는 MCP 대신 `scripts/figma.mjs`를 쓰고, `pull` 한 번(API 3회)으로 받은 캐시만 읽는다. 팀원 시트로 모자라면 유료 플랜이나 한 사람이 받아 나누는 방법을 정한다 |
| 컴포넌트 라이브러리(daisyUI 등)를 쓸지 | 쓰지 않는다. Tailwind만 쓰고 공통 UI는 `components/`에 직접 만든다. 디자인 시안이 나온 뒤 다시 정한다 |
| `package.json`에 의존성을 추가하는 변경을 기능 PR과 따로 올릴지 | 따로 올리지 않는다. 추가하기 전에 팀에 묻는 것으로 충분하다고 본다 |
| 기능 이슈를 어느 저장소에 둘지(기능 하나가 백엔드와 프론트 양쪽에 걸친다) | 정해지지 않음 |

## 백엔드와 같이 정할 것

| 항목 | 지금은 이렇게 한다 |
| --- | --- |
| 응답 JSON 형식(`{success, data, error}`)과 오류 코드 이름, `fields`의 필드 이름 | 공통 모듈이 정해 둔 형식 |
| 응답 JSON에서 Y/N 컬럼이 `"Y"`로 올지 `true`로 올지, 코드 컬럼이 `"01"`로 올지 이름으로 올지 | 정해지지 않음. 화면이 쌓이기 전에 정해야 한다. 정해지기 전에는 변환 유틸을 미리 만들지 않는다 |
| 로그인 실패의 상태 코드(400 계열 중 무엇) | 정해지지 않음 |
| AI 서버의 응답 모양과 오류 코드를 메인 서버(`{success, data, error}`)와 같게 할지 | 같다고 보고 `aiApi`에 같은 인터셉터를 붙인다. 다르면 `aiApi`의 인터셉터를 따로 만든다 |
| 목록의 `sort` 값: 대소문자(`popular` / `POPULAR`), 목록에 없는 값이 왔을 때(400 / 기본 정렬) | 정해지지 않음. 정렬이 있는 목록을 처음 만드는 사람이 백엔드 담당과 정한다 |
| 로그인(Spring Security) 구현 시점 | 백엔드 구현 중 가장 마지막. 그 전에는 새 화면을 `ProtectedRoute`로 감싸지 않고, 헤더에서 `useMe`로 로그인 여부를 가르지 않는다(로그인 화면이 아직 쿠키를 심지 못해 `/auth/me`가 항상 401로 실패한다). 백엔드는 개발 프로필에서 모든 요청을 허용한다. 로그인을 붙일 때 `routes/domains/<도메인>/<도메인>Routes.js`에서 로그인이 필요한 화면 그룹의 `auth`를 `'member'`로 바꾸고(`AppRoutes.jsx`가 `ProtectedRoute`로 감싼다), 헤더를 `useMe`에 연결한다 |

## 프론트 담당이 정할 것

| 항목 | 영향을 받는 곳 |
| --- | --- |
| 로딩을 화면에 어떻게 보일지(스켈레톤 / 스피너) | 전체 |
| `features/` 폴더 목록을 백엔드 도메인(`member`, `pet`, `health`, `community`, `place`, `support`, `notification`, `expense`)과 같게 할지 | 전체 |
| 채팅 소켓 클라이언트의 위치(`features/chat/socket.js` 예정) | 채팅 |
| 관리자용 API 함수와 훅의 위치. 한 도메인 것은 `features/<도메인>/`, 여러 도메인을 합친 대시보드는 `features/admin/`으로 백엔드와 맞출지 | 관리자 화면 |
| 폼 입력 검증을 어떻게 할지(직접 / 라이브러리) | 입력 화면 |

## 하네스 개선 후보

하네스(`/start`·`/verify`·`/end`)를 시험하며 나왔지만 치명적이지 않아 미뤄 둔 것. 쓰다가 같은 문제를 다시 겪으면 여기에 적고, 흐름이 멈추거나·검증 없이 잘못된 코드가 커밋되거나·남에게 영향이 갈 때 고친다.

| 문제 | 지금은 이렇게 한다 |
| --- | --- |
| 사람이 일부만 확인했다고 답해도 마일스톤을 `끝`으로 바꿀 수 있다 | `/end`가 확인 못 한 것을 밝히고 되돌릴지 묻는다. 사람이 답한다 |
| `/verify`는 기획 밖 변경을 파일 단위로만 본다. 기획에 없던 동작(예: 인증 방식 추가)은 비고로만 남는다 | `/verify` 비고와 PR 리뷰에서 본다 |

# E2E 테스트 시나리오

사용자 여정(E2E-01~15, 보완 E2E-34~36)과 백오피스 연동(관리자→사용자 E2E-16~28, 사용자→관리자 E2E-29~32, 관리자 기록 E2E-33)으로 나뉜다.

- 목적: 화면·기능 단위 TC(`TC_*.md`)로는 잡히지 않는 **도메인 사이 연동**을 사용자 여정 단위로 확인한다
- 기준: 각 도메인 TC와 같음(코드 origin/develop 0e1e99a 2026-11-10, 요구사항정의서 v0.10.6). 단계의 세부 기대 결과는 적어 둔 FN의 TC를 따른다. 이 문서는 **단계 사이에 값이 넘어가는지**만 따로 적는다
- 표기: ⛓ = 도메인 경계(이 시나리오에서 꼭 확인할 연동 지점), ⚠ = 지금 코드·서버 때문에 막히거나 일부만 되는 단계
- 우선순위: 상 = 출시 전 반드시, 중 = 2차 교차 테스트 때, 하 = 시간 날 때

## 준비

- 서버: 백엔드 :8080, AI 서버 :8000, 프론트 `yarn dev`(:5173). 알림·메일 확인용 메일함
- 계정: **A**(일반 회원, 반려동물 2마리·캐릭터 있음), **B**(일반 회원, 반려동물 1마리), **N**(가입 전 이메일), **관리자 C**
- 브라우저: 팝업 허용(AI 대화창·채팅 새 창). 두 계정을 동시에 보는 시나리오는 일반 창 + 시크릿 창
- 배치 실행: 관리자 배치 현황(`/admin/batches`)에서 수동 실행

## E2E-01 신규 가입부터 첫 반려동물·캐릭터까지 (상)

목적: 새 회원이 첫 화면에서 막히지 않고 "내 반려동물이 보이는 메인"까지 도착한다.

| # | 화면 | 동작 | 확인 |
| --- | --- | --- | --- |
| 1 | 랜딩 `/` | [로그인]·[회원가입]으로 들어간다 | FN-COM-003-04 |
| 2 | 회원가입 `/signup` | 약관 → 이메일 인증 → 휴대전화(필수) 중복확인 → 비밀번호 → 가입 | FN-ACC-001-11~14·29·30 |
| 3 | 가입 직후 닉네임 모달 | 기본 닉네임을 바꿔 저장 | FN-ACC-001-22·26 |
| 4 | 로그인 `/login` | 이메일 로그인 | FN-ACC-002-05 |
| 5 | 메인 `/main` | 반려동물 0마리 안내와 [반려동물 등록하기] | FN-MAN-001(이름 없는 인사말), FN-MAN-008 |

| 7 | ⛓ 메인 | 다시 메인으로 | 인사말에 방금 등록한 이름, 바로가기에 "종합 건강기록" 타일 1개 (FN-MAN-001·008) |

# 백오피스 연동 테스트

관리자 화면 TC는 "관리자 화면에서 저장됐다"까지만 본다. 여기서는 그 값이 **회원 화면에 실제로 반영되는지**(관리자→사용자)와 **회원 행동이 관리자 화면에 잡히는지**(사용자→관리자)를 본다.

- 두 창을 나란히 둔다: 일반 창 = 관리자 C, 시크릿 창 = 회원 A(또는 B)
- **반영 시점** 칸이 기대와 다르면 결함이다. 즉시 = 회원 화면 새로고침 1번 안, 다음 날 = 자정 배치 뒤, N초 = 그 주기 안
- 관리자 쪽 단계에서 저장이 성공하면 감사 로그에도 남아야 한다(E2E-33에서 모아 본다)
- 관리자 화면은 지금 수정 중이다. 관리자 TC를 갱신할 때 아래 FN 참조를 다시 맞춘다

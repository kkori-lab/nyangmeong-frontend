# TC · 관리자(SCR-ADM-*) 수동 테스트 케이스

- 기준: 관리자_기능명세서_v0.4_20261101 (SCR-ADM-*), 프론트 `src/features/admin*`·`batch`·`audit`·`apiUsage`·`setting/admin`·`src/pages/admin/` 코드, 백엔드 `docs/api/*.md`의 `/admin/...` 행과 `ErrorCode.java`, `milestones/LJS.md`(2026-11-04)
- 준비: 백엔드를 :8080에 띄우고, 프론트는 `yarn dev`(:5173)로 띄운다. 관리자 계정 1개와 일반 회원 계정 1개를 준비한다. 회원·게시글·신고·문의 샘플 데이터가 DB에 있어야 한다
- 표기: P = 정상, N = 오류·경계, 연동 = 다른 화면·배치와 이어지는 확인. 기대 결과의 따옴표 문구는 코드·ErrorCode에 있는 문구 그대로다. `확인 필요: ...`는 코드·계약에서 근거를 찾지 못한 부분이다
- 상태 표기: 화면마다 `상태:`를 적었다. "가짜 응답(백엔드 연결 전)"은 `features/*/api.js`가 메모리·sessionStorage 가짜라서 새로고침하면 처음 값으로 돌아가거나 서버와 무관하게 움직인다. 이 화면의 TC는 가짜 기준이고, 연결 뒤 다시 돌려야 한다
- 공통 규칙(아래 TC마다 반복하지 않는다)
  - 일반 회원이 관리자 주소(`/admin/...`)를 직접 입력하면 화면 가드(`ProtectedRoute`)가 메인(`/`)으로 보낸다. 비로그인이면 로그인 화면으로 보낸다. 서버가 403(`ADMIN_ONLY`·`FORBIDDEN`)을 주면 화면은 `AdminForbidden`(제목에 서버 문구 "관리자만 접근할 수 있습니다.", 아래 "관리자 계정으로 다시 로그인해 주세요.", [메인으로])을 보여 준다. 각 화면의 "일반 회원" TC는 가드 이동을 확인한다
  - 서버 꺼짐: 실제 API 화면은 백엔드를 끄면 그 화면의 조회 오류 문구와 [다시 시도]가 보이고, 백엔드를 켜고 [다시 시도]를 누르면 목록이 나온다. 가짜 응답 화면은 네트워크를 쓰지 않아 서버를 꺼도 오류가 나지 않는다. 대신 dev 서버에서 주소 뒤에 `?fake=error`(조회 오류), `?fake=forbidden`(403)을 붙인다. 지원하지 않는 화면은 각 TC에 적었다
  - 저장 실패(서버 400·404·409)는 모달·폼이 닫히지 않고 입력이 유지되며 서버 문구(`error.message`)가 폼 아래에 보인다
  - 목록 하단은 `총 N건 · 20건씩`(화면에 따라 건수 표기 다름), 쪽 번호는 주소의 `?page=`에 남아 새로고침해도 유지된다
- 제외(TC 없음): FN-ADM-100-01~04(결번, 공통코드 화면 없음), FN-ADM-073-01(결번), FN-ADM-060-01~05(SCR-ADM-060 장소 화면을 2026-11-04 사람 결정으로 없앰), FN-ADM-101-02(지역 조회, 2026-11-03 화면에서 뺌), FN-ADM-023-07(결번), FN-ADM-050-04(결번)

# 펫돌봄 일정 기한·채팅 종료 처리 백엔드 요청서

백엔드 저장소에서 `/start`로 기획할 때 붙여 넣는다. 클래스 이름은 백엔드 코드를 읽어 확인한 것이고, 결정 전인 항목은 따로 표시했다. (작성 2026-11-13, KSJ)

## 0. 확정된 정책

| 항목 | 값 |
| --- | --- |
| 돌봄 시작일 | 오늘부터 90일 이내 |
| 돌봄 종료일 | 시작일부터 30일 이내 |
| 일정 협의 가능 글 | 작성 후 30일이 지나면 마감 |
| 종료일이 지난 모집중 글(매칭 없음) | 지난 날 바로 마감 |
| 완료 글·종료 채팅방 목록 숨김 | 완료·종료 후 7일 (삭제 아님, 숨김) |

프론트는 날짜 선택기와 폼 검사에 90일·30일을 이미 넣었다. 서버 검증이 없어 API를 직접 부르면 우회된다.

## 1. 글 등록·수정 날짜 기한 검증

- 대상: `CareRecruitmentCreateRequest`, `CareRecruitmentUpdateRequest`의 `prtcBgngDt`·`prtcEndDt`.
- 시작일이 오늘 이전이거나 오늘+90일 이후면 `INVALID_INPUT_VALUE`.
- 종료일이 시작일+30일을 넘으면 같은 오류.
- 수정에서 날짜를 바꾸지 않았다면 이미 지난 날짜여도 저장을 허용한다(프론트와 같은 규칙).

## 2. 지난 글 자동 마감 (배치)

- `CareMatchNoResponseJob`처럼 community 안에 새 배치를 둔다. 매일 00:00 KST 실행을 제안한다.
- 대상: `RCRT_STTS=PCAC0001`(모집중)이고 매칭이 없는 글.
  - 일정이 있는 글은 `prtcEndDt`가 지난 글.
  - 일정 협의 글은 작성 후 30일이 지난 글.
- 처리: 글 상태를 `PCAC0003`으로 바꾼다. 상태 변경 이력은 기존 `changeRecruitmentStatus`를 쓴다.
- 매칭 완료 이후 단계는 건드리지 않는다(거래 진행 중).
- 응답에 구분값 추가: 화면이 매칭 없이 마감된 글을 「모집 종료」, 실제 거래가 끝난 글을 「거래완료」로 나눠 보여 준다. 목록·상세 응답에 "매칭 이력이 있었는지" 값이 필요하다. 필드명은 서버 규칙에 맞게 정한다. 프론트는 그 키를 그대로 쓴다.

## 3. 완료·종료 목록 7일 숨김

- 펫돌봄 글 목록: `RCRT_STTS=PCAC0003`이고 완료 후 7일이 지난 글을 기본 목록에서 제외한다. 작성자의 「내 글만 보기」(`mineYn=true`)에는 포함한다. 상세 조회는 막지 않는다(채팅방 「돌봄 글 보기」 링크).
- 채팅 목록(`ChatRoomSummary`): 종료된 방(`chatRoomSttsCd`가 읽기 전용 `CHTC0002`이거나 매칭 상태 `EXPIRED` `PCAC0018`)이 종료 후 7일이 지나면 일반 채팅 목록에서 제외한다. 돌봄 글의 「채팅 목록 보기」(`listPstSn`) 조회에서는 계속 포함한다.
- 현재 `ChatRoomSummary`에는 종료 시각이 없다. 숨김 판단은 서버에서 하고 프론트는 받은 목록만 그리는 방식을 추천한다.
- 숨김 일수 `7`은 시스템 설정값(`SYS_STNG`)으로 두면 운영 중에 바꿀 수 있다.

## 4. 채팅 서버 차단

- 종료 방 메시지 차단: `ChatMessageService`가 방이 읽기 전용이거나 매칭이 `EXPIRED`이면 새 메시지를 거부한다. 프론트는 입력창을 이미 막았다.
- 나가기 차단: `leaveChatRoom`이 매칭완료·확인 대기·수령 대기(`PCAC0013`·`PCAC0014`·`PCAC0015`)에서는 거부한다. 프론트는 메뉴만 비활성화했다.

## 5. 거래 취소 요청 (매칭 완료 이후) — 정책 승인됨, 상세는 기획에서 확정

현재 `CareMatchController`의 `cancel`은 수락 전(`REQUESTED`) 전용이다. 매칭 완료 뒤에는 나가기가 유일한 취소 수단이어서, 4번의 나가기 차단과 반드시 같이 가야 한다.

- 요청: 매칭완료·확인 대기·수령 대기 단계에서 사유(코드+내용)와 함께 요청한다. 사유는 필수이고 시안은 다음과 같다.
  - 일정이 맞지 않게 됐어요
  - 상대와 연락이 어려워요
  - 조건이 달라졌어요
  - 기타(직접 입력 필수)
- 상대가 동의하면 거래가 취소(`PCAC0017`)되고 방이 읽기 전용이 되며, 글 상태는 모집중으로 되돌린다(기존 `cancelOnLeave`와 같은 처리).
- 상대가 거절하면 거래가 이어지고, 요청자가 철회할 수 있다.
- `GET /chat-rooms/{sn}` 응답에 취소 요청 정보(요청자, 사유, 상태)를 실어 준다. 화면이 요청한 쪽·받은 쪽 카드를 이걸로 그린다.
- 시안: https://claude.ai/artifact/AUy2P1X6vTR1Ep4Qyy9zR5 (로그인한 본인 계정에서만 열림. 필요하면 아래 5단계로 복원)
  1. 채팅방 메뉴: 「거래 취소 요청」 추가, 「채팅방 나가기」는 흐리게 막고 안내
  2. 요청 확인 창: 사유 선택(필수) + 「취소 요청 보내기」
  3. 요청한 쪽 카드: 대기 표시 + 「요청 철회하기」
  4. 받은 쪽 카드: 사유 + 「취소에 동의」·「거절하고 계속」
  5. 취소 완료: 입력창 읽기 전용, 나가기 켜짐
- 정해야 함: 상대가 응답하지 않을 때의 기한(자동 철회, 자동 취소 등).

## 6. 팀 결정이 먼저 필요한 것

| 항목 | 현황 | 선택지 |
| --- | --- | --- |
| 수령 대기 무기한 | `CareMatchNoResponseJob`이 수령 대기를 종료하지 않는 것은 2026-11-06 사람 결정. 보호자가 수령을 확인하지 않으면 글이 영원히 매칭완료이고 두 사람은 나갈 수도 없음 | 알림(7일·12일째) + 14일 자동 완료 추천 / 분쟁 접수 |
| 거래 취소 요청 무응답 기한 | 미정 | 자동 철회 또는 자동 종료 |
| 개인정보 보관 기간 | 미정 (숨김과 별개) | 1년 후 주소·사진 정리 등 |

## 프론트 후속 작업 (서버가 끝난 뒤)

- 「모집 종료」 구분 표시, 숨김 반영.
- 거래 취소 요청 화면 5단계 (서버 응답 필드명을 그대로 사용).
- 일정이 지난 매칭완료 글의 안내 문구는 서버 없이 프론트에서 바로 가능.
